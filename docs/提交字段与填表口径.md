## 题目信息（两次跑共用，只填一次）

| 字段 | 类型 | 可选项 / 说明 |
|---|---|---|
| User Prompt | 文本 | 本题完整 prompt 原文，直接粘贴，不摘要不改写；两次跑必须完全一致 |
| 任务类型 | 单选 | `0-1代码生成` `feature迭代` `Bug修复` `代码理解` `代码重构` `工程化` `代码测试` |
| 任务难度 | 单选 | `困难` `地狱`（本期禁简单、中等） |
| 语言/框架 | 文本 | 主要语言与框架，多个用逗号分隔，例：`Go, Gin, PostgreSQL` |
| Harness | 单选 | `Claude Code` `Codex CLI`（本项目用 Codex CLI） |
| Harness 版本 | 文本 | 客户端版本号，**必填**；两次跑必须同一个版本 |
| 操作系统 | 单选 | `MacOS/Linux` `Windows` |
| 环境可复现等级 | 单选（选填） | `无外部依赖` `有外部依赖，未容器化` `已容器化，可一键起环境` |
| 初始环境快照 | 文本(URL) | 两次跑共同起跑点，commit permalink，40 位完整 SHA |

`环境可复现等级` 口径：

- `无外部依赖`：clone 后即可运行；
- `有外部依赖，未容器化`：依赖数据库、外部服务或本机特定配置，无法直接重跑；
- `已容器化，可一键起环境`：仓库内提供 docker-compose 或等价的一键启动方式。

## 第一次跑（A）／第二次跑（B），两组各自填写

| 字段 | 类型 | 说明 |
|---|---|---|
| A/B-SessionID | 文本 | 本次跑的会话 ID，两次是两个不同的会话 |
| A/B-轨迹文件 | **附件** | 本次跑的轨迹文件。把 `~/.codex/sessions/`（或 `~/.claude/projects/`）下对应的 jsonl 上传到对象存储，填可直接下载的链接 |
| A/B-产物快照 | 文本(URL) | 本次跑结束后的 commit permalink，40 位完整 SHA，**父提交必须是初始环境快照** |
| A/B-运行录屏 | **附件** | 本次跑产物的运行录屏：从干净状态启动、展示真实输出、90 秒以内、720p、mp4；**无法运行的也必须录，录出报错** |

注意：轨迹文件和运行录屏在**正式表里是附件字段**（文档内嵌的说明表里写的是 URL 文本，
以正式表为准 —— 附件形式两处都满足）。

## GSB

| 字段 | 类型 | 说明 |
|---|---|---|
| GSB 结论 | 单选 | `A 更好` `Same` `B 更好`；只有两次确实难分高下时才选 Same |
| GSB 理由 | 文本 | 必填，写法见 `GSB理由写法与合格示例.md` |

## 其他

| 字段 | 类型 | 说明 |
|---|---|---|
| 备注 | 文本 | 其他需要说明的问题 |
| 提交人 | 人员 | 本人，与飞书显示名一致 |
| 提交时间 | 日期 | 完成本轮打分的时间 |
| 有效性 | 单选 | `有效` `作废-工程故障` `作废-环境未重置` `作废-其他`，默认「有效」 |
| 是否有异议 | 单选 | 有异议时填，并在备注说明 |

`有效性` 口径：因网络波动、请求失败等**工程故障**导致某次跑不完整，或第二次跑前
**忘记把工作区 reset 回初始快照**，选对应的作废原因并在备注里说明。
