我们跑团老要现编地牢，干脆想自己写个小工具：给个种子就生成一张地牢，看着顺眼那种。

生成参数给在 samples/presets.json 里了，四套不同风格，常用种子在 samples/seeds.txt，格式 README 里有，别改。

界面上一边是参数（房间大小、房间数、走廊宽度、环路数、宝箱房数量），一边是网格地图。改个参数点一下重新生成，
得即时看到差别，别让我等半天。

三件事我比较在乎。

第一，同一个种子必须一模一样。同一套参数加同一个种子，今天生成和明天生成、我笔记本和公司电脑上，画出来得逐格相同。
所以生成器里别直接用 Math.random()，得有自己的随机源，而且生成过程的先后顺序也得稳，不能因为遍历对象顺序变了
结果就变。种子允许是随便一串字符，不是只能填数字。

第二，地图得发得出去。生成完给我一条链接，别人打开就是我这张图，参数和种子都在链接里。别长得离谱，
我不想发一条几百字符的出去。还有，别人手贱改链接把参数改坏了，得能识别出来给个提示，别直接白屏——
这是不可信输入，得当回事。

第三，地图得是能用地牢，不是一堆连不上的房间。所有房间必须连通、出生点到宝箱房得有路、
参数互相打架的时候（房间太多地图太小）得能优雅退化，不能卡死也不能画出重叠的墙。这几条我要看到你真验证过，
不是嘴上说连通。

另外能导出图片、能复制坐标就行，编辑器不用做。

别引库别 npm 别构建，原生 ES module 加 Canvas。README 里说一下随机源怎么设计、链接怎么编码、连通性怎么保证的。
