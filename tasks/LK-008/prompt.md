我们跑团的时候老要现编地牢地图，干脆想自己写个小工具：给个种子就生成一张地牢，看着舒服的那种。

生成参数我给在 samples/presets.json 里了（四套不同风格），常用的种子在 samples/seeds.txt，
格式 README 里有，别改。

想要的：

左边一排参数（房间大小、房间数、走廊宽度、环路数、宝箱房数量），点一下重新生成；右边画网格地图。
参数随手改，改完即时看到差别，不要每改一个参数要等半天。

三条我最在意的：

第一，**同一种子必须一模一样**。同一套参数 + 同一个种子，今天生成和明天生成、在我的笔记本和在公司电脑上，
画出来必须逐格相同。所以生成器里的随机不能直接用 `Math.random()`，要有自己的随机源，而且生成过程的先后顺序
也要稳定（不能因为遍历对象的顺序变了结果就变了）。种子允许是任意字符串，不是数字。

第二，**地图要发得出去**。生成完要能生成一条链接，别人打开就是我这张图，参数和种子都在链接里。
链接别长得离谱（我不想发一条几百字符的），而且别人手改链接把参数改坏的时候，要能识别出来给个提示，
不能直接白屏——这是不可信输入，得当回事。

第三，**地图得是"能用"的地牢**，不是一堆连通性没保证的房间：所有房间必须连通、出生点到宝箱房要有路、
参数互相打架的时候（房间太多地图太小）要能优雅退化而不是卡死或者画出重叠的墙。这几条我要看到你验证过，
不是嘴上说连通。

另外加个"导出图片"和"复制坐标"就行，不用做编辑器。

硬约束：不要第三方库、不要 npm、不要构建步骤，原生 ES module + Canvas。

做完留个 README：怎么开、随机源怎么设计的、链接编码格式、连通性怎么保证的。
