我们在做一个网页版的工厂流水线小游戏（内部代号 beltworks）：玩家在网格上铺传送带和机器，把矿石一路加工成齿轮，在时限内送进仓库。机器、配方、关卡数据都在仓库里了（data/machines.json、data/recipes.json、data/levels.json、samples/blueprint_demo.json），模拟器和界面你来写。

技术上：纯静态，原生 ES module，不引构建工具、不装依赖，起个静态服务就能玩。核心逻辑（tick 模拟、传送带、配方、统计）拆成单独模块，用 node --test 写测试。

一、时间与模拟

固定步长模拟，data/levels.json 里的 tick_rate 是 10（每秒 10 个 tick）。模拟必须是纯函数式的推进：给一个状态和 N 个 tick，输出新状态，这样能单步调、能测试、能重复。

二、传送带

传送带占一格，有朝向（上下左右）。物品在传送带上按 ticks_per_tile（见 machines.json，5 个 tick 走一格）前进。前方一格已经有物品就堵住，整条带子往后排队，不许穿模。

三、机器

机器每 ticks_per_cycle 完成一次配方（配方在 recipes.json）。规则定死：

- 采矿机必须放在矿脉格上（levels.json 的 ore_nodes）才能工作，产出 ore，不需要输入。
- 其他机器开工前要凑齐输入：从**任意相邻格上的传送带物品**里取，优先取"最靠前"的那件。
- 产出放到 facing 方向相邻的那一格：是传送带就放上去（满了就等，等的时候不消耗输入），是地面就堆在那里（一堆最多 4 件），是另一台机器就交给它。
- 机器卡住的时候（缺料/输出堵）要在界面上看得出来。

四、目标

关卡目标是把 goal.count 件 goal.item 送进仓库（levels.json 的 exit 那几格），只有真的送进去了才计数。时限是 time_limit_ticks 个 tick，超时算失败，可以重开。

五、操作

左侧是工具面板（采矿机/熔炉/组装机/传送带），点选一种再到地图上点一下放置；传送带支持按住拖拽连续铺；R 键旋转朝向；右键拆除（拆除时把上面的物品一并清掉）。放置要挡住非法位置（压到矿脉以外的地方放采矿机、压到出口、越界）。

六、界面

网格渲染出来，矿脉、机器、传送带箭头、带上的物品、出口都要一眼能分清；显示目标进度、剩余时间；显示"过去 60 秒的实际产量"（个/分钟），这是判断产线有没有堵的关键指标。要能暂停、单步一个 tick、1x/2x/4x 加速。
蓝图能存到 localStorage 再载回来（samples/blueprint_demo.json 是格式样例），刷新页面不丢当前关卡。
美术还没出，纯 CSS 画，别引图片和字体。
