想做个网页版的小工厂游戏，核心就一件事：铺传送带和机器，把矿石加工成齿轮，限时送进仓库。数据和配方都在仓库里（data/machines.json、data/recipes.json、data/levels.json）。

先说时间。模拟按固定 tick 走，levels.json 里 tick_rate=10，也就是一秒 10 个 tick。你要是把逻辑写在 requestAnimationFrame 里按帧推，120Hz 和 60Hz 的机器跑出来产量不一样，这个我踩过，别再来一次。给我一个能"推进 N 个 tick"的东西，我要能单步看、能测、能重复跑。

传送带占一格、有朝向，物品按 machines.json 里的 ticks_per_tile（5 tick 一格）往前挪。前面那格已经有东西就堵着排队，不能叠。这条我比较在意——堵没堵得一眼看出来才好玩。

机器这边规则定死：采矿机得放在矿脉格上（levels.json 的 ore_nodes）才干活；别的机器开工前要凑齐 recipes.json 里的输入，输入从相邻传送带上取，优先取最前面那件；产出放到朝向的那一格——是传送带就放上去，满了就等着，等着的时候别消耗输入；是地面就堆着，一堆最多 4 件。哪台机器因为缺料或者堵住停工了，界面上要看得出来，不然我根本不知道产线断在哪。

目标是把 N 个齿轮真的送进仓库（exit 那几格），堆在外面不算数。超时算失败，能重开。

操作：左边一排工具（采矿机/熔炉/组装机/传送带），选完在地图上点一下就放；传送带能按住拖着连续铺；R 转朝向；右键拆，拆的时候把带上的东西一起清掉。放不了的地方（矿脉以外放采矿机、压到出口、越界）就别让它放。

界面除了网格，我还想要一个"过去一分钟实际产量（个/分钟）"的显示，判断产线有没有堵全靠它。再加暂停、单步、1x/2x/4x。蓝图能存 localStorage 也能读回来（samples 里那份 json 就是格式样例），刷新别把当前关卡弄丢。
