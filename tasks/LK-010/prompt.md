我们运维的配置越来越多，我想做个网页版的配置编辑器：配置长什么样、能填什么，全部由一份 schema 决定，
以后加字段只改 schema。

schema 和两份配置样例都在 samples 里，简化版的写法 README 里有，别改这些文件。

想要的：

左边按 schema 渲染出表单，右边实时显示当前配置的 JSON。改表单右边跟着变，反过来直接改 JSON 也要能同步过去
（改坏了别炸，先把错误提示出来让我继续手改）。

要支持的字段类型和约束 README 里都列了：字符串长度、数字范围、枚举、布尔、数组（有上限、元素还有类型）、
嵌套对象。嵌套对象和"数组里放对象"这两种我在 samples/schema.json 里都用了，别只做一层。

三条重点：

第一，**校验要能给到具体位置**。不是弹一句"配置不合法"，而是告诉我 `upstreams[2].weight` 超了、
`limits.qps` 缺了、`name` 太长。而且校验要在输入的过程中就跑，不能等点保存才算。

第二，**schema 变了不能把已有配置搞坏**。以后我给字段加一个默认值、加一个必填、把枚举加一个选项，
老配置贴进来要能识别出缺失的字段并补上默认值，同时把"补了什么、哪里需要人工确认"列出来。
这条要真做出来，我加字段是每周都在发生的事。

第三，**要能对比两个版本**。samples 里有 config.json 和 config-v2.json，我想选两份配置看差异：
哪几个字段改了、数组里多了/少了哪一项（要按元素内容对，不能整段标红），改了的字段还要能一键用回旧值。

性能上也别太糊弄：schema 大一点、数组里几十项的时候不能一改一个字就卡住。

硬约束：不要第三方库、不要 npm、不要构建步骤，原生 ES module。

做完留个 README：怎么开、schema 支持的完整语法、默认值补齐的策略、对比是怎么算的。
