我们运维的配置越堆越多，想做个网页版编辑器：配置长什么样、能填什么，全由一份 schema 定，
以后加字段只改 schema。

schema 和两份配置样例都在 samples 里，简化版写法 README 里有，这些文件别改。

左边按 schema 渲染表单，右边实时显示当前配置的 JSON。改表单右边跟着变；反过来直接改 JSON 也得同步过去，
改坏了别炸，先把错提示出来让我接着改。

字段类型和约束 README 里列了：字符串长度、数字范围、枚举、布尔、数组（有上限、元素还有类型）、嵌套对象。
嵌套对象和"数组里放对象"这两种 samples/schema.json 里都用了，别只做一层。

三件事。

校验得能给到具体位置。别弹一句"配置不合法"就完了，要告诉我 upstreams[2].weight 超了、limits.qps 缺了、
name 太长。而且输入过程中就要跑，不能等点保存才校验。

schema 变了不能把老配置搞坏。以后我加个默认值、加个必填、枚举加个选项是常事，老配置贴进来要能认出缺的字段
补上默认值，同时把"补了什么、哪里要人确认"列出来。这条得真做，我每周都在加字段。

还得能对比两个版本。samples 里有 config.json 和 config-v2.json，我想选两份看差异：哪几个字段改了、
数组里多了少了哪一项，数组要按元素内容对，不能整段标红；改过的字段能一键用回旧值。

性能也别太糊弄，schema 大一点、数组几十项的时候，不能敲一个字就卡一下。

别引库别 npm 别构建，原生 ES module。README 写一下支持哪些语法、默认值怎么补、对比怎么算的。
