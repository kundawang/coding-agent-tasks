我们要给前端性能做个体检，想做个网页版的压测面板：按一份工作负载描述，在页面上真跑一堆活，
把耗时统计出来，并且能在不同机器、不同时间跑出能对比的数。

工作负载我写在 samples/workload.json 里了，格式 README 里有，别改。

想要的：

点开始之后，按 workload 里的权重抽任务，真在页面上干活——渲染两千行列表、给两万行排序、
算两兆数据的哈希、过滤五万行——不是空转计个数。跑 warmup 次预热不计入，然后正式跑 runs 次，
每次记总耗时，最后给出：平均、中位数、p90、p99、最快最慢各是多少。这些数要能看出来抖动大不大。

三条重点：

第一，**同一份工作负载、同一个种子，跑两遍的数要对得上**。所以抽哪些任务、每次任务用多少数据，
都得由种子决定，不能依赖 `Math.random()` 的隐式状态。页面上要能填种子，也得支持 `?seed=`，
这样我在两台机器上跑同一个种子才谈得上对比。报告要能导出、也能把别人的报告导回来并排比较。

第二，**跑的时候页面不能死**。一轮要跑几十次、单次可能几百万次操作，如果同步跑页面会僵住，
进度条都不动。得分片跑，让界面保持响应、能中途取消，取消之后已经跑完的那部分数据要能留下。

第三，**统计不能自欺欺人**。预热必须真的把结果扔掉；单次结果太离谱的（比如被别的标签页抢了 CPU）
要能识别出来标出来，而不是直接混进平均里；p99 这种分位数别用四舍五入糊过去，
要按真实排序或者正经的分位算法算，并且把你用的算法写进 README。

还有个小要求：连续跑多轮，内存不能一路涨（跑完要能看到用的内存大致回到开始的样子）。

硬约束：不要第三方库、不要 npm、不要构建步骤，原生 ES module；图表用 Canvas 自己画就行，不放外部库。
