我们几个想搞个打飞机的弹幕游戏在浏览器里玩。之前同事写过一版，子弹一多就卡成 PPT，屏幕上过一千发就开始掉，
掉到 30 帧那手感直接没法看，后来就没人碰了。

这次想好好做。关卡我用 JSON 写好了在 samples/stage.json，自机参数在 samples/ship.json，你照那格式读就行，
这俩别动。先把这关跑通。

操作就是上下左右加一个射击键，按住自动连发。有个事我得先说清楚：判定只能用机体验中间那个小点，
飞机画得再大也只是好看，不能整个机身碰一下就死。这是弹幕游戏的命根子，做错了这游戏就没法玩。

性能是真要命。这关最狠的一波同时能喷出上万发子弹，得稳住 60 帧。别每帧 new 一堆对象丢给 GC 去收，
也别写成"先生成全部再逐个过滤掉出屏的"，那样一发就废。对象池也好别的办法也好，你自己想。

还有个我很看重的，整局要能重现。开局给个种子，从那以后弹幕往哪散、敌人啥时候来、随机偏多少，
全得走同一个随机源。同一个种子加同一串按键，结果必须一模一样。页面上要能填种子，也能从地址栏读，像 ?seed=xxx。

我想录下来复盘，所以得能把这局的种子和我的按键序列导出成一段记录，别人贴回来能一帧一帧放出来，
看我到底怎么死的。格式你定，README 里说一下。

还有逻辑别跟渲染帧率绑死。上一版我掉一帧之后明明躲过去了还是被判中弹，气死了。逻辑固定步长跑，画面只是画它。

别引库别 npm 别搞构建，原生 ES module 加 Canvas 就行，我 python -m http.server 开。README 里把判定点怎么算、
种子和记录格式讲一下。弹幕生成、碰撞、回放这些纯计算的东西能拆出来单独跑就更好了。
