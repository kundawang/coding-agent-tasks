我们几个一直想在浏览器里玩弹幕射击，之前同事写过一个版本，子弹一多就卡成幻灯片——他那个只要屏幕上超过
一千发就开始掉帧，掉到 30 帧手感就全毁了，最后没人玩。这次想认真做一个。

关卡我已经用 JSON 描述好了放在 samples/stage.json 里，自机参数在 samples/ship.json，格式你打开看就明白，
这两个文件别改。先让这一关完整跑通。

我想要的效果：

操作就是上下左右加一个射击键，按住射击自动连发。判定用**判定点**——只有很中间那个小圆点是会中弹的，
机体大一圈只是好看，这是弹幕游戏的命根子，不能做成"整个飞机碰到就死"。

性能是这题最重要的。这一关最难的地方一波要出几十发弹源、每发弹源喷几十发子弹，同时屏幕上几千到上万发
是常态，得稳在 60 帧。别每帧 new 一堆对象又扔给 GC，也别说"先生成再过滤"——那样一次全屏遍历就废了。

还有一个我很在意的：**整局要能复现**。开局给个种子，从那一刻起弹幕怎么散、敌人什么时候来、
随机偏移多少，全都走同一个随机源；同一种子 + 同一串按键，结果必须一模一样。页面上要能填种子、
也要支持 `?seed=`

我要能录下来回放：把种子和我的按键序列导出来，别人贴回来能一帧一帧重放，用来复盘刚才怎么死的。
记录格式你自己定，写进 README。

另外自机和弹幕的碰撞、弹幕和弹幕的互斥这些判定，帧率越高越准是应该的，但**不能因为掉一帧就让判定跑偏**——
逻辑要有固定步长，渲染只是画。这条我在上一版踩过坑，掉帧之后人明明躲过去了还是被判定中弹。

硬约束：不要第三方库、不要 npm、不要构建步骤，原生 ES module + Canvas，我 `python -m http.server` 直接开。

做完留个 README：怎么开、判定点怎么算的、种子和记录格式怎么用。纯计算的部分（弹幕生成、碰撞、回放）
