我平时爱做那种"谁喝什么饮料养什么宠物"的推理题，但网上都是人手写的，出几道就重样了，想自己写个程序生成，再做个网页界面来做题。配置在 data/puzzle_config.json：4 个人、4 种饮品、4 种宠物、4 种乐器。

线索就五种，我按自己习惯命名的，别改名字：position（某个值排在第几位）、same（两个值在同一个人身上）、not_same（不在同一个人）、neighbor（两个人的位置挨着）、left_of（a 在 b 左边）。json 里都有例子。

生成这块是重点，也是我搞不定的地方：随机出一个排列当答案，然后从候选线索里抽，每抽一条都用求解器验一下。我要的最终结果必须同时满足两件事——**唯一解**（没有第二种排法能满足所有线索），以及**每条线索都删不掉**（随便去掉一条，就会出现多解）。所以不能凑够条数就收手，得能删就删、删到不能再删。难度就控制线索条数的上限（配置里写了 easy/normal/hard 各多少条）。seed + 难度决定同一道题，同一个 seed 要出同样一题。万一某个 seed 死活凑不出满足条件的题，就往后顺延一个 seed 并在 README 里说明，别卡死。

求解器就是回溯，规模这么小乱搜也够用，但我要求一道题 100ms 内能判出唯一解、多解还是无解——生成的时候要反复调用，慢了整题都很卡。

界面：三个 4×4 的网格（人物×饮品、人物×宠物、人物×乐器），每格三种状态来回点：不知道 / 确定是 / 确定否，颜色要一眼分得开。鼠标悬停某人或某种饮品时行列高亮。右边列线索，我自己判断满足没满足就行，你要标也可以但别乱标。撤销重做要有，至少 50 步。另外两个按钮：检查——**别直接告诉我答案**，只把跟线索矛盾、或者跟我自己的标记打架的格子标红；提示——用求解器算出一个必定成立的格子帮我标上，提示次数要显示出来。全都标对了算通关，显示用时/步数/提示次数。

题目要能导出成 json、也能导入还原（格式跟 samples 里那份一样）。美术没有，纯 CSS。
