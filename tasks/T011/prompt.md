我们在做一个网页版的逻辑推理游戏（内部代号 clueforge）：几个人各自有不同的饮品、宠物、乐器，玩家根据一堆线索把对应关系推出来。题目不要人工写，要程序生成。类别和难度配置在 data/puzzle_config.json，题目格式样例在 samples/puzzle_demo.json。

技术上：纯静态，原生 ES module，不引构建工具、不装依赖，起个静态服务就能玩。生成器和求解器是纯逻辑，拆成单独模块，用 node --test 写测试。

一、线索类型（都在 clue_types 里）

- position：某个值排在第 n 位（1 开始）
- same：两个值在同一个人身上
- not_same：两个值不在同一个人身上
- neighbor：两个值的人相邻
- left_of：a 所在的人排在 b 的左边

二、生成器要求（这块是重点）

1. 用 seed 驱动自研 PRNG，同一个 seed + 同一个难度必须生成同一道题。
2. 先生成一个随机排列作为**唯一解**，再从所有候选线索里抽线索，每抽一条都要用求解器验证"目前仍然唯一解"。
3. 生成结果必须同时满足两条硬指标：
   - **唯一解**：没有任何其他排列能同时满足所有线索；
   - **最小**：线索集合里任意一条被删掉，解就不再唯一（多解）。
   所以不能抽够了就停——要能删就删，删到不能再删为止。
4. 难度决定线索条数的**上限**（easy/normal/hard 见配置），别超。
5. 如果某个 seed 死活生成不出满足最小性的题，就顺延到下一个 seed 并说明（写进 README），不要死循环。

三、求解器

实现一个约束求解（回溯就行）。要求：4 个类别 × 4 个取值的规模下，求解一次在 100ms 内出结果，并且能判断"唯一解 / 多解 / 无解"三种情况——生成器和后面的"检查"都要用它。

四、玩家界面

- 主界面是三个 4×4 的标记网格（人物 × 饮品、人物 × 宠物、人物 × 乐器），每格三种状态：未知 / 确定是 / 确定否，点击循环切换，颜色要能一眼分清。
- 鼠标悬停某一行或列时，相关行列高亮；线索面板按类型分组，已满足/未满足可以看出来（你自己定判定口径，写进 README）。
- Ctrl+Z / Ctrl+Shift+Z 撤销重做，至少 50 步。
- "检查"按钮：**不要直接给答案**，只标出与线索矛盾、或者与玩家已确定的标记冲突的格子。
- "提示"按钮：从当前局面出发，用求解器算出一个"必定成立"的格子并帮玩家标上，同时累计提示次数显示在界面上。
- 全部标记与唯一解一致时判定通关，显示用时、步数、提示次数。
- 题目能导出成 JSON、也能导入 JSON 还原（格式跟 samples/puzzle_demo.json 一致）。

五、其它

同 seed 同难度要能复现同一道题；换种子换难度立刻出新题。美术还没出，纯 CSS 画，别引图片和字体。
