我们几个周末凑一起玩卡牌构筑那种游戏，最近想自己做一个网页版的原型，先在群里传着玩。就做单机，
一个人打 AI。

规则我按我们平时玩的抄了个简化版写到 README 里了，卡表和一局的双方配置在 samples/ 下，
格式你打开看就懂。这两个文件别改。

我想要的效果：

卡得是数据驱动的。现在这 18 张牌是按 samples/cards.json 里那几种效果拼出来的，我想加一张新牌
只用改 JSON、不用动代码。你要是在代码里给某张牌写一段专门的逻辑，那就算没做对。

随机要能复现。一局开始时给一个种子，从那一刻起，牌堆怎么洗、什么时候抽到什么、AI 打哪张，
全都得走同一个随机源；同一个种子跑同一串操作，结果必须一模一样。页面上要能填种子，
也要支持从地址栏读，比如 ?seed=12345，这样我把种子发到群里，别人能跑出完全一样的一局。

整局要能导出成一段记录，别人把这段贴回来能一步步重放：从开局到结束，每一步的手牌、能量、
双方血量、身上的状态都要对得上。我主要拿这个复盘，谁输了就贴出来大家一起看是哪一步打错了。
记录格式你自己定，写进 README。

中途关掉再打开要能接着打，别丢进度（localStorage 就行）。

非法操作必须挡住，而且不能把状态弄脏：能量不够还点牌、点了不该打的目标、动画还在放的时候
连点两下，都得拒绝掉，不扣能量、不改任何数。这条我比较在意——上一版就是连点两下同一个攻击
结算了两次，白多打一下，那次比赛就因为这个吵起来了。

AI 要走和玩家完全一样的接口，它不能偷看牌堆、也不能直接扣血，只能靠出牌。策略按 README 里
写的来就行，不用多聪明。

硬约束：不要第三方库、不要 npm 装东西、不要构建步骤，原生 ES module；用 DOM 还是 Canvas 你
自己看着办。我到时候 python -m http.server 直接开。

做完留个 README，写清楚怎么开、记录格式长什么样、种子怎么填。结算、取整、洗牌、AI 决策这些
纯计算的部分能拆出来单独跑最好，方便我拿几个种子对一遍。
