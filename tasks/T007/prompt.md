我们在做一个网页版卡牌对战小游戏（内部代号 embervault），先只做单场战斗的原型：一个玩家打一个敌人。规则数据和样例已经放仓库里了（data/cards.json、data/relics.json、data/enemies.json、samples/replay_demo.json），页面和引擎你来写。

技术上：纯静态，原生 ES module，不引构建工具、不装依赖，起个静态服务就能玩。核心逻辑（随机数、伤害结算、状态、洗牌、回放）拆成单独模块，用 node --test 写点测试，别只靠人肉点页面。

一、回合流程

玩家生命 80，每回合能量 3，抽 5 张牌，手牌上限 10（抽超了的牌直接进弃牌堆）。牌堆抽空就把弃牌堆洗回去接着抽。
每个玩家回合按这个顺序开始：算能量 → 结算中毒（中毒无视格挡，扣完层数 -1）→ 触发"回合开始"类遗物 → 抽牌。
玩家点"结束回合"后，敌人按它亮出来的意图行动，然后回到玩家回合。任意一方生命 ≤ 0 战斗结束，敌人先死算赢。

二、超载

每张牌除了 cost 还有 overload，表示"记到下回合的欠费"。本回合能量够 cost 就能打，overload 不占本回合能量；下回合开始时能量 = max(0, 3 − 上回合累计 overload)，然后累计值清零。所以超载牌是抢节奏用的，但要还。

三、状态

- 格挡：挡伤害，回合开始时清零
- 中毒：回合开始按层数扣血（无视格挡），然后层数 -1
- 虚弱：造成的伤害 -25%，回合结束层数 -1
- 易伤：受到的伤害 +50%，回合结束层数 -1

伤害结算顺序固定：基础伤害 → 攻击方有虚弱就 -25% → 受击方有易伤就 +50% → 先扣格挡再扣血。每一步向下取整，最低 0。一张牌里多个效果按数据里的顺序结算（比如破甲是先打伤害、再加易伤，不是反过来）。

四、遗物

按 relics.json 里的 order 从小到大触发。余烬核心：你的回合开始时给 3 点格挡。毒囊：敌人获得中毒层数时额外 +1 层（一张牌只触发一次，别自己触发自己）。

五、敌人

意图按 enemies.json 里的顺序循环，玩家回合里要能看见敌人下回合要干什么。敌人行动时也先结算它自己身上的状态（中毒、虚弱同理），再按意图打出来；它自己的格挡在它回合开始时清零。

六、可回放（这条最重要）

所有随机（洗牌、随机选目标）必须由 seed 驱动的自研 PRNG，写清楚用的是哪个算法。同一个 seed + 同一串操作，重放出来的战斗必须完全一致。
每种操作记一条日志（打出手牌第几张、结束回合），战斗中途和结束都能导出日志；界面上要有"回放"，拿 seed + 日志重放，重放结束时双方血量、格挡、状态层数、手牌、牌堆顺序、能量都要和原来一模一样。samples/replay_demo.json 就是一份 seed + 操作序列的样例。
