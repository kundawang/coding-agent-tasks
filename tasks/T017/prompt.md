想做个网页版的"涂地"对战小游戏：两边各四个单位，谁把地面涂成自己颜色多谁赢，两分钟一局。场地和单位数据我整理好了放仓库里（data/arena.json、data/units.json），界面和战斗逻辑你来写。

纯静态，原生 ES module，不引构建、不装依赖。逻辑必须和渲染分开：逻辑按固定 tick 推（arena.json 里 tick_rate=30），渲染用 requestAnimationFrame 插值画，掉帧不能影响结果。核心逻辑（涂色、墨水、AI、结算）拆出来，用 node --test 写测试。

规则：

- 地面是一张格子（cols×rows），每格归属于"玩家/敌方/中立"。单位站过的地方、喷到的范围都会被涂成自己颜色；涂色按单位朝向喷：line 类型沿朝向喷一条（宽 width 格），circle 类型喷半径 radius 的圆。喷的时候每 tick 扣 ink_cost 点墨水，墨水空了就喷不出来，只能靠自然回蓝或者踩地面上的补墨点（ink_pads，回蓝快三倍）。
- 走路速度按 units.json 的 speed（格/秒）换算到每 tick；撞到障碍物（obstacles）会被挡住，不能穿。
- 打人：喷到敌方单位就掉血（每下 damage_per_hit，间隔按武器射速），血量归零后回出生点复活，respawn_seconds 秒后满血出来。血量会缓慢自回。
- 结算：时间到（match_seconds）按各自涂到的格子数占比算胜负，别只看有人没血。

我要的界面：canvas 画整个场地，格子颜色一眼能看出归属；两边各有一队小血条和墨水条；右上角显示双方涂地百分比和剩余时间；被杀/复活要有明显提示（不然玩家莫名其妙就发现自己回出生点了）。

另外两点我比较在意：

1. 电脑对手（AI）要能打：给它一个简单但像样的策略——优先去涂没人涂的地方、墨水见底就找补墨点、看到敌人就喷。别傻站着，也别全场乱跑。AI 的随机必须走 seed。
2. 一局的操作要能记录（每 tick 的方向 + 是否喷漆），同 seed + 同一串输入必须复现出完全一样的涂色结果；samples/input_log.json 是格式样例，能导出/导入。
