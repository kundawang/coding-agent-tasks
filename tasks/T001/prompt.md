我们内部有个小的数据管道服务 pipeline-svc（就在当前目录），日报聚合那类任务都跑在它上面。现在有几个问题一直没解决，你帮我改掉。

1. 每次 python -m pipeline run 都把全部 stage 从头跑一遍。spec 一个字没改，昨天刚跑过的结果也白跑。库里本来就存着每个 stage 的结果，希望复用起来：一个 stage 的输入（上游结果 + 它自己的配置）跟上次一样，就直接拿上次的结果，不要再执行。

2. 跑到一半挂掉（比如某个 export 写文件失败），重启只能从头再来。希望重新执行时，已经跑成功、输入也没变的 stage 不要再跑，只重跑没跑完的或者输入变了的。

3. 现在只要有一个 stage 失败，整个运行直接抛异常中断，跟它没关系的那条分支也跟着白跑。希望改成：失败的 stage 标 failed 并且能看到失败原因，它下游的 stage 标 blocked 不执行，其它不依赖它的分支继续正常跑完；最后的整体状态要能反映这次是成功、部分失败还是失败。

4. spec 里依赖写成了环的时候，现在只报一句 "cannot determine execution order"，完全看不出是哪几个 stage 成环。希望报错里带上完整的环路径（例如 a -> b -> c -> a）。

5. 线上已经有一批旧版本建的 .db 文件（表结构和当前一致，仓库里有 tests/fixtures/legacy_state.db 这个样本），升级后必须还能直接打开继续用，不能要求删库重建。

另外，现在库里的数据是脏的：某次失败的运行会把 spec 里已经跑过的 stage 结果覆盖进去，出现新旧混着、dump 出来对不上的情况。顺手一起收拾掉。

要求：

- 命令行用法别动（python -m pipeline run <spec> --db ... --out ...，以及 dump 的参数），每个 stage 一行的输出格式和最后的 status 行保持原样。
- 现有测试必须继续通过，该补的测试你补上。
- 只用标准库，不要引第三方包。
- 代码风格跟现有保持一致。

跑测试：python -m unittest discover -s tests
