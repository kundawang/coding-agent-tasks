想做个网页版的深海采集小游戏：你背着一罐氧气往下潜，捞到东西再活着上来，赚的钱用来买装备。分区和装备数据我放仓库里了（data/zones.json、data/gear.json），模拟和界面你来写。

纯静态，原生 ES module，不引构建、不装依赖。逻辑按固定步长推（zones.json 里 tick_rate=10），渲染用 requestAnimationFrame；纯逻辑（氧气预算、深度、采集、威胁、结算）拆出来用 node --test 测。

机制：

- 深度分三档：浅滩 0-50、海沟 50-120、深渊 120-200。越深越黑（visibility 就是你能看到的半径，探照灯能加半径）、资源越值钱、威胁越狠（threats 里有每分钟触发概率和每秒扣氧量）。
- 氧气消耗是叠加的：基础（o2_base_per_sec）+ 上下潜/平移（o2_per_move_sec）+ 采集（o2_per_drill_sec），深度还会再乘一个 pressure_penalty（深水更费气）。
- 船壳有耐久：超过 pressure_safe_depth（gear.json 里 60 米）之后，每往下 10 米每秒扣血，血归零就沉了、这次收获全丢。
- 采集袋有容量（gear 的 bag.capacity），满了就装不下了；捞上来的东西按 value 换钱，装备可以升级（气罐/推进器/灯/钻头/袋子）。
- 上浮必须留够氧气：氧气见底就是"沉底"，直接结算失败。这条我要在界面上看得见——顶部一条氧气条，再画一条"按当前深度上浮回水面需要多少气"的虚线，玩家得自己算够不够。

界面：左边是深度剖面（三档颜色分带，你的位置上下移动，资源点和威胁用不同图案；能见度之外的区域不显示内容），右边是氧气/船壳/背包/当前深度和收获列表；下面一条日志（"海沟 87 米：发现珍珠 ×1""深渊 133 米：被暗流打断采集，扣气 8"）。

另外：

- 所有随机（资源生成位置、威胁触发）走 seed，同 seed + 同一串操作必须复现完全一样的一次下潜。samples/route.json 是操作记录的格式样例，能导出/导入回放。
- 存档放 localStorage（钱、装备等级、已解锁装备）。
