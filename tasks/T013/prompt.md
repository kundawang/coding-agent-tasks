想做个网页小游戏，玩法是"你先给机器人写一段指令，然后两个机器人自动打"。我小时候玩过那种要塞指令的机器人对战，一直想要一个能自己调程序的版本。数值和指令集我整理好了放仓库里（data/units.json、data/program_spec.json），页面和引擎你来写。

纯静态，原生 ES module，不引构建、不装依赖。指令解释器和模拟是纯逻辑，拆出来用 node --test 写测试。

程序就是一段 JSON：每条规则是「什么时候 + 做什么」，从前往后匹配，命中第一条就执行它的动作，然后本 tick 结束。条件是 enemy_within / hp_below / energy_above / weapon_ready / wall_ahead / always，动作是 move（前/后/左/右）、turn、face enemy、fire、wait、charge。这些都在 program_spec.json 里，字段名别改，我后面还要写别的程序。

模拟按 tick 走（units.json 里 tick_rate=10，一局 match_ticks 个 tick）。机器人有血、能量、移动速度、转向速度、传感器距离和武器（伤害/射程/冷却）。开火条件是武器冷却好 + 敌人距离 ≤ 射程 + 朝向夹角 ≤ 15 度；命中就扣血，没打中也要进冷却（就当放空了）。能量：move/turn 每 tick 扣 1，charge 回 2，能量不够的动作直接跳过（不要卡住，继续判下一条规则）。撞墙就是停下来，不要穿过去。

我要的效果：

- 左边写程序（能在 JSON 里直接编辑，也能加/删规则），右边是战场俯视图，点"开打"就跑整局，能调速度、能暂停、能单步一个 tick。
- 单步的时候要看得到当前 tick 的判定过程：匹配到哪条规则、执行了什么动作、双方血量能量多少。调程序全靠这个，不然我根本不知道为什么它不按我想的走。
- 打完给结果（谁赢、剩余血量、打了多少发、命中率），能给"同样子再打一次"和"换种子"。
- 所有随机（出生点、障碍布局）都走 seed，同一份程序 + 同一个 seed 必须跑出完全一样的过程；要能把一整局的指令日志导出，再拿 seed + 日志回放。samples/match_demo.json 是示例（一段程序 + seed），格式照它来。
