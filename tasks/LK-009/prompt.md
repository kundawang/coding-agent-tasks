我们做代码评审经常得离线干活，飞机上、客户现场，GitHub 那个界面打不开。想自己做个网页小工具：
把 diff 粘进去，一行行留批注，完事导出一份记录发群里。

样例在 samples 里：diff.patch 是我们真实的 diff，comments.json 是已经留过的批注。README 有格式，别改。

左边 diff 一行行带增删标记，点哪行就能在右边留批注。批注必须锚在具体的行上，不是锚在"第 12 条"，
而是新版文件的哪一行，同时记下对应的旧行号（新加的行就没有旧行号）。这条我最在意：上一版我们用的是
按顺序数行数的做法，别人改一下 diff 的顺序，所有批注全错位了，那次评审直接废了。所以删除的行、
重命名的文件、新文件、hunk 被截断这些都得处理对。

已经留过的批注要能导回来：comments.json 直接贴进工具，一条条重新落到正确的行上。落不上的单独列出来
告诉我为什么——文件没了？那行被删了？不能默默丢掉。

我常在没有网的地方改，所以本地得存住（localStorage 就行），关掉再开批注还在。联网之后要把自己这份
和别人的合并，两边都改了同一行得能看出来是冲突，不能悄悄覆盖掉一条。

最后导出的记录能直接发群里，别人打开能把批注全还原。

别引库别 npm 别构建，原生 ES module，我 python -m http.server 开，也别连网、别调接口。
README 说一下批注锚定怎么算、冲突怎么处理、记录格式。
