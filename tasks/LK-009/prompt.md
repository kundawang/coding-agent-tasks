我们做代码评审经常要离线干活（飞机上、客户现场），GitHub 的界面打不开。我想自己做个网页版的小工具：
把 diff 粘进去，逐行留批注，完事导出一份记录发群里。

样例我放在 samples 里了：diff.patch 是我们真实的 diff，comments.json 是已经留过的批注。格式 README 里有，别改。

想要的：

左边是 diff，一行一行带增删标记；点任意一行就能在右边留批注。批注必须**锚在具体的行**上——
不是锚在"第 12 条"，而是新版本文件的哪一行，同时记下对应的旧行号（如果这行是新加的那就没有旧行号）。
这一条是我最在意的：上一版我们用的是"按顺序数行数"的做法，别人改一下 diff 的顺序，所有批注就全错位了，
那次评审直接废了。所以锚点要经得起 diff 变化，删除的行、重命名的文件、新文件、被截断的 hunk 都要处理对。

已经留过的批注要能导回来：comments.json 直接贴进工具，要能一条条重新落到正确的行上，
落不上的要单独列出来告诉我为什么（文件没了？那行被删了？），不能默默丢掉。

我经常在断网环境下改，所以本地要能存住（localStorage 就行），关掉再开批注还在；
联网之后把自己这份和别人的那份合并——两边都改了同一行要能看出来是冲突，不能悄悄覆盖掉一条。

最后导出的记录要能直接发群里，别人打开能把批注全部还原。

硬约束：不要第三方库、不要 npm、不要构建步骤，原生 ES module，我 `python -m http.server` 直接开。
不要连网、不要调任何接口。

做完留个 README：怎么开、批注锚定怎么算的、合并冲突怎么处理、记录格式长什么样。
