手头在做一个回合制战棋的小原型，想放到网页上试玩：先只做一张地图，我方 3 个打敌方 3 个。纯静态页面就行，起个 http server 打开能玩。兵种数值和地图我按表格导成 json 放仓库里了（data/units.json、data/map_01.json），你按数据来，别把数值写死在代码里，我后面还要调平衡。

地图是 8 行 ASCII，`.` 平地、`#` 是墙（不能走、挡视线）、`^` 高地（站上去打人疼 25%）、`o` 掩体（站里面挨打少 2 点）。部署点我写在 json 里了，我在左下、敌人在右上。

单位一轮能做两件事：动一次、打一次（或者待命），动完还能打。移动只能上下左右，不能斜着走，也不能穿墙穿人；move 是几就只能走几格，绕路也占格数。

攻击看两个条件：距离不超过 range（按格子数算曼哈顿距离），视线不能被墙挡住。视线怎么判你自己定一个规则，写清楚、可复现就行，我倾向按格子中心连线。

伤害我算好了：max(1, damage + 高地加成 - 目标护甲 - 掩体减免)，高地加成是 damage 的 25% 四舍五入。别自己再加别的系数，我调平衡的时候要能一眼看懂。

回合按速度排：活着的单位按 speed 从高到低轮，同速的玩家先；轮到谁谁的行动点就满上。一轮里我方全动完才轮到敌方，敌方动完回合数 +1。打满 turn_limit（在 map json 里）回合没分胜负算平局。

AI 我要求不高，但必须确定——同一个局面每次跑出来都得一样。能一击打死人的优先打，打不死就挑性价比最高的；够不着就往最近的敌人那边靠，落点优先高地、其次掩体，尽量别站进我的攻击范围。别让它在原地来回磨。

另外我要能回放：我每点一下（选谁、走哪、打谁、结束回合）都记一条，之后拿 seed + 这份日志重放，双方血量、位置、行动点、回合数必须一模一样。之前我那个原型是拿 Math.random 洗的，qa 复现不了，我调了一下午，这次一定要能重放。data/orders.json 是日志样例。

界面：地图画出来，地形一眼能分辨；单位分色带血条，当前能动的那个高亮；选中之后把能走的格子和能打的目标标出来，点目标就打。边上放行动日志和结束回合按钮，顶上显示回合数和双方还剩几个。打完弹结果，能给"同样子再来一局"。美术还没画，纯 CSS 就行，别引图片字体。
