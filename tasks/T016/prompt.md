想做个网页版的审讯推理小游戏：一间茶铺打烊后丢了现钱，店里还剩三个人，你只能在有限的问话次数里问、出示物证、最后指认一个人。案件数据我写好了放仓库里（data/case_01.json），界面和推理引擎你来写。

纯静态，原生 ES module，不引构建、不装依赖。对话推进、证据解锁、结局判定、剧本校验这些拆出来，用 node --test 写测试。

数据结构你看一眼就明白：每个人有一组对话节点，节点可以有 requires（先问过哪些节点）和 requires_evidence（要先出示哪件物证）才会出现；问完会 sets 一些 flag。结局按 flag 判定（endings）。问话次数上限在 limits 里（12 次）。

我想实现的效果：

- 左边是人物和可用问题列表，不可用的问题要显示"为什么会解锁不了"（比如"需要先出示监控片段"），别直接藏起来，不然玩家不知道自己在干嘛。
- 物证栏能点选"出示"，出示后对方会改口/露馅（比如小柯先说自己 21:30 走了，看到监控就改成"我在锁门"）。出示证据不占问话次数，但每件物证每人只能用一次。
- 时间线面板：把已知的时间和说法按顺序排出来，互相矛盾的地方标红（比如"21:30 离开"和"21:35 后巷人影"）。这块我想让玩家一眼看到矛盾，不用自己记。
- 用完次数或者主动指认就结算：指对人 + 拿到关键 flag = 真相结局；指错人 = 指错了；次数用完还没定案 = 证据不足。
- 要有一个"剧本校验"的命令行入口（node --test 里也行）：读 case_01.json，检查有没有问不到的节点（requires 永远满足不了）、有没有节点指向不存在的证据、有没有结局永远达不成、有没有 flag 设了没人用。我后面还要自己写案件，这个校验必须能跑。

操作日志要能导出，同 seed + 同一串操作（问话/出示/指认）得到同样的结局；samples/playthrough.json 是格式样例。
