我这边想让你帮我写个网页版的打歌游戏，就是音游那种，四条轨道往下掉音符、到判定线按对应的键。

背景是这样：我们组年会下午有个午休打歌赛，投影到会议室大屏，同事轮流上来打一把，最后留个榜。
会场网很烂，所以我不想要后端，纯静态页面起个服务能打开就行。曲子也先不要素材——我们没有能商用的
曲子，你直接用 WebAudio 现场合成一个 8-bit 味道的伴奏，比节拍器好听一点就够。

谱面我扒了一首放在 samples/chart.json 里，三分钟、804 个音符，格式你打开看一眼就明白，别改它。
先把这一首完整跑起来。

我想要的效果：

四个键，我习惯用 D F J K。判定我想的是三档：±30ms 以内 Perfect、±60 算 Great、±100 算 Good，
再往外 Miss。数值你觉得不合适可以调，但最后用了多少要写在 README 里。连击要显示，断了归零。
打完出一页成绩：Perfect / Great / Good / Miss 各多少、最大连击、准确率、总分，我想拿这个当排名依据。

音乐和判定得是同一条时间轴，伴奏按 chart 里的 bpm 和 offsetMs 合成，别自己另起一套节奏。
上次同事用 setTimeout 做了一版，我开高刷屏（165Hz）整首歌就往前偏，掉一帧更夸张。所以我最在意的是
这个：以音频时钟为准，画面只是跟着渲染，掉帧不能影响判定结果。

还有键盘延迟。我这边按下去到浏览器收到事件大概十几毫秒，换台机器又不一样。我想要个校准界面：
屏幕上打四拍，我跟着点四下，它算出我这台机器的偏移，之后判定里自动补上，并且记住，下次打开还在。
校准完和没校准的成绩得能明显看出区别，不然这东西等于没做。

暂停也要能用。按 Esc 音乐停、音符停在原地，回来接着打，不能整体错位，暂停那段时间也不能算进去。

窗口随便拖、按全屏，判定都不能漂。年会上是大屏投影，回家我拿笔记本练，两边分辨率差很多，
切来切去也不能出问题。

年会那天是大家轮流上，所以一把打完要能填个名字存成绩（localStorage 就行），按分数排序；
另外能导出成一段 JSON 我发群里，别人把 JSON 贴回来能合并进去。

长条音符、按住不放这些先不要，我还没想好怎么画，先把普通音符做扎实。

硬约束就一条：不要第三方库、不要 npm 装东西、不要构建步骤，原生 ES module + Canvas 就行，
我到时候 python -m http.server 直接开。另外这首曲子节奏挺密的，不能掉帧掉到没法打。

做完留个 README，写清楚怎么开、判定窗口最后定的多少、校准怎么算的。测试不强求，
纯计算的部分（判定、校准、计分）能拆出来单独跑最好。
