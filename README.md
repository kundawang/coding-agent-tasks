# cornerstore

街角小店的经营模拟，网页版。进货、上架、定价、应付顾客，关掉网页再回来生意还得接着做。

纯静态、无构建、无依赖。

## 目录

```
samples/goods.json   商品目录
samples/store.json   开店初始状态
```

## 商品格式

```json
{
  "id": "milk",
  "name": "鲜牛奶",
  "costCents": 320,
  "shelfLifeDays": 7,
  "popularity": 0.8,
  "slotSize": 1
}
```

| 字段 | 说明 |
|---|---|
| `costCents` | 进价，**单位是分**（整数） |
| `shelfLifeDays` | 保质期，过期只能丢 |
| `popularity` | 受欢迎程度，0~1，影响顾客买它的概率 |
| `slotSize` | 占几个货架位 |

价格一律**用分做整数运算**，界面上显示成元。

## 初始状态

```json
{
  "cashCents": 500000,
  "shelfSlots": 24,
  "dayLengthMs": 240000,
  "customersPerDay": 120,
  "stock": [{ "goodsId": "milk", "qty": 6, "boughtOnDay": 1 }]
}
```

`dayLengthMs` 是一天折算成多少真实毫秒（现在是 4 分钟 = 一天），这样试玩的时候不用等。

## 运行

纯静态、原生 ES module，没有构建和依赖。但模块和 JSON 都靠 `fetch` 加载，
浏览器不允许 `file://` 页面发这类请求，所以要在目录里起个静态服务器，
仓库自带一个零依赖的 `serve.mjs`（只用 Node 内置模块，不用 npm 装东西）：

```
node serve.mjs          # 默认 8123 端口，浏览器开 http://本机IP:8123
```

组内网里用 nginx/caddy 直接挂这个目录也行。存档只在浏览器 `localStorage`（key：`cornerstore.save`）。

## 怎么玩

- 商品卡片里填数量点“进货”：扣整数分现金、占货架位；位不够或钱不够会被拒绝。
- 售价用“元”填写（精确到分，如 `5.50`），内部一律换成整数分。
- 每 `dayLengthMs`（默认 240000ms = 4 分钟真实时间）结算一个游戏日。
- 每天开门先扔当天已到保质期的货（`boughtOnDay + shelfLifeDays <= 今天`），再做生意。
- 卖货按批次先进先出（先进的批次先卖），尽量减少过期。

## 顾客与定价

- 一天的顾客数按均值 `customersPerDay` 做泊松抽样；日内时间片按比例缩放均值。
- 每个顾客在“当前还有货且没过期、且已定价”的商品里，
  按 `popularity × 定价吸引力` 加权挑一件；另有一个固定的“扭头就走”权重。
- 定价吸引力是条明确有落差的曲线：
  - 售价 = 进价时吸引力 = 1；
  - 售价到进价的 1.8 倍时归零（中间是凸曲线，1.4 倍大约只剩三成多）；
  - 0 元视为吸引力 1（免费送，不赚钱）。
- 所以抬价要在“单件利润”和“成交概率”之间权衡，定价差异在销量上肉眼可见。

## 离线怎么算

游戏只存“当前游戏日开始的真实时间戳” `dayStartMs`，不存连续心跳。
打开页面（以及页面长时间切后台后回来）时：

1. `elapsed = 当前时间 - dayStartMs`。
2. 按 `floor(elapsed / dayLengthMs)` 个**完整游戏日**逐日重放：
   每天用存档里的确定性随机种子跑同一套顾客模拟，卖掉的记账、翻篇、扔过期货，
   结果写入“每日结算”历史。
3. 最后不足一天的零头按时间比例抽顾客，收入计入“今天”，不送天数。
4. **最多补 7 个完整游戏日**（`MAX_CATCHUP_DAYS`）。超出部分整段丢弃：
   不结算、不送钱、不扣货，锚点对齐到“现在”作为新一天的起点，
   并在“异常记录”里写一条“离线封顶”。
5. 弹窗报告逐项写清：补了几天、营收多少分（含零头会注明）、卖出多少、
   成交/流失人数、扔了哪些过期货、封顶丢了几天。一关一开（不足一天）不送天数。

## 时间回拨怎么处理

- `elapsed < -2000ms`（`ROLLBACK_IGNORE_MS`，留 2 秒给 NTP/校时抖动）判定为回拨。
- 策略是“往保守靠”：
  - 本次**不结算任何收益**，也不扣已有的现金和库存；
  - 天数不变（前一天已经结算掉的历史和钱保留）；
  - 当天未走完的进度清零，游戏时钟重新锚到“现在”；
  - “异常记录”里永久留一条红色“时间回拨”，写明回拨幅度和处理方式，
    并弹窗告知玩家。
- 回拨之后再把时间往前拨，也只能从干净的新锚点起算、照旧受 7 天封顶，
  刷不出额外天数。

## 存档升级

- 存档带 `version` 字段，当前为 `1`。
- 读档时先按版本走 `js/migrate.js` 里的迁移链
  （`MIGRATIONS[源版本]`，以后加字段就在这里加一步并抬高 `SCHEMA_VERSION`），
  再跑一遍 v1 字段级兜底：缺字段补默认、类型非法修默认、库存/价格逐条清洗。
- 所以老存档（包括没有版本号的、被手改缺字段的）只会被补齐继续玩，
  不会清档报错；实际修过什么会写进“异常记录”里的“存档升级”条目。
- 存档 JSON 彻底损坏时，原文隔离备份成 `cornerstore.save.corrupt.<时间戳>`，
  再开新档并留一条异常。
- `samples/` 以后新增商品时，老存档会自动给新商品补默认售价（进价 × 1.3）。

## 代码结构

```
index.html          页面骨架
styles.css          样式
js/config.js        常量（封顶天数、回拨阈值、定价曲线参数等）
js/money.js         分 <-> 元的字符串换算（不碰浮点）
js/rng.js           确定性随机（mulberry32 + 泊松）
js/migrate.js       存档版本迁移链与字段级兜底
js/storage.js       localStorage 读写与损坏隔离
js/game.js          进货/定价/顾客模拟/过期/日结算/离线/回拨
js/ui.js            DOM 渲染、结算弹窗
js/main.js          启动、迁移、离线补算、游戏循环
test/core.test.mjs  纯逻辑测试：node --test test/core.test.mjs
```
