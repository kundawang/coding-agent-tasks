# cornerstore

街角小店的经营模拟，网页版。进货、上架、定价、应付顾客，关掉网页再回来生意还得接着做。

纯静态、无构建、无依赖。

## 目录

```
samples/goods.json   商品目录
samples/store.json   开店初始状态
```

## 商品格式

```json
{
  "id": "milk",
  "name": "鲜牛奶",
  "costCents": 320,
  "shelfLifeDays": 7,
  "popularity": 0.8,
  "slotSize": 1
}
```

| 字段 | 说明 |
|---|---|
| `costCents` | 进价，**单位是分**（整数） |
| `shelfLifeDays` | 保质期，过期只能丢 |
| `popularity` | 受欢迎程度，0~1，影响顾客买它的概率 |
| `slotSize` | 占几个货架位 |

价格一律**用分做整数运算**，界面上显示成元。

## 初始状态

```json
{
  "cashCents": 500000,
  "shelfSlots": 24,
  "dayLengthMs": 240000,
  "customersPerDay": 120,
  "stock": [{ "goodsId": "milk", "qty": 6, "boughtOnDay": 1 }]
}
```

`dayLengthMs` 是一天折算成多少真实毫秒（现在是 4 分钟 = 一天），这样试玩的时候不用等。

## 运行

纯静态，原生 ES module，没有依赖、没有构建。因为页面要 `fetch` samples 里的 JSON，
直接双击 `index.html`（`file://`）会被浏览器拦，在本目录起个静态服务即可，例如：

```
npx serve .            # 或 python -m http.server 8000
```

## 玩法

- 每个顾客一天来一次，先按商品 `popularity` 分流到某件在架商品，再按你的**售价/进价比**决定买不买。
- 定价曲线（界面里每个商品都实时显示成交率提示）：
  - 售价 ≤ 进价：成交率约 90%，但亏钱；
  - 售价 = 进价 × 1.5（建议价）：成交率约 50%；
  - 售价 = 进价 × 3：成交率约 8%；
  - 售价 ≥ 进价 × 10：成交率为 0，定价高就是没人买；
  - 售价填 0 视为白送，不计成交也不挣钱。
- 卖掉的货物按进货批次**先进先出**；同一天补的货并入当天批次。
- 货架按 `slotSize` 计位，位不够进不了货。
- 每天结算（`dayLengthMs` 到期）时：卖出的计收入和成本，没卖的继续上架；
  批次在结算时若 `boughtOnDay + shelfLifeDays <= 新的一天`，整批扔掉，按进价计入"过期报损"。
- 所有钱都用**整数分**运算，界面再换成元显示；千分位由代码手工分组，几千万分也不会失真。

## 离线怎么算

游戏时间锚在真实时钟上：存档里记 `lastSeenMs`（上次见到玩家的时间）和 `dayStartMs`（当天起点）。

- 再次打开（或切回标签页）时，用 `现在 - lastSeenMs` 算出经过了多少个 `dayLengthMs`。
- 只有**完整过完的整天**才结算，不足一天的零头并进当前这一天，所以一关一开不会白送一天。
- 补算**最多 7 天**（`MAX_CATCHUP_DAYS`）。超过 7 天的部分直接不补、也不累计，
  回来时当天进度条从零开始走。
- 补算和在线走的是同一个 `advanceTime` / `simulateDay`：一样要交过期报损，不会因为离线就免死。
- 回来时弹横幅写明：补了几天、营业收入多少、净利润多少、过期报损多少、有没有撞上限、
  被砍掉几天；每天的数字在"每日报表"里逐天可查，事件记录里也有一条 `offline-settled`。

## 时间回拨怎么处理

- 若 `现在 < lastSeenMs` 且回拨超过 30 秒（`CLOCK_SKEW_MS`，容忍正常的 NTP 校时抖动），
  判定为时间回拨。
- 回拨区间**一律不结算**：不补任何收益、不推进游戏天数、商品也不因为这段时间过期
  （即不能靠回拨刷"新的一天"，也不会因为调时间意外损失货物）。
- 界面上弹红色横幅明示发生过回拨及大约分钟数，事件记录里永久留一条 `clock-rollback`
  （带原始 `skewMs`）。把系统时间调回真实时间后，游戏从原锚点继续正常走天。
- 30 秒以内的小幅倒退视为抖动，忽略，不记账。

## 存档怎么升级

存档在 localStorage 的 `cornerstore.save.v1` 键下（键名固定，版本号存在数据内部）。

- 数据带 `version` 字段，当前是 **2**。v1 就是 `samples/store.json` 的形状
  （现金、货架、天数时长、顾客数、库存、定价）。
- 读档后走迁移链：`1 -> 2` 的迁移在 `js/save.js` 的 `migrate1to2` 里，
  真实补齐 `shopName / day / dayStartMs / lastSeenMs / reports / events` 等字段，
  老数据原样保留，不清档、不报错。以后加版本只需在 `MIGRATIONS` 里再挂一个函数。
- 迁移完还有一层规范化（`normalizeState`）：缺字段补默认、类型不对的丢弃、
  商品目录里已不存在的库存批次剔除、缺失的定价回填建议价。所以手改坏半个存档也能接着玩。
- 读到**更高版本**（在别处玩了新版又回到老页面）不删档，按已知字段兜底加载并提示。
- JSON 彻底损坏无法解析时，原文备份到 `cornerstore.save.v1.corrupt-backup` 再新开一档，
  并在界面和事件记录里说明，绝不静默吞掉玩家数据。

## 自测

纯逻辑（金额、定价曲线、日结算、过期、货架、离线封顶、回拨、存档迁移）有 Node 自测：

```
node tests/selftest.mjs
```
