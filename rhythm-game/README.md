# 午休打歌赛 · 四轨音游

纯静态网页音游：四轨音符下落，`D F J K` 击打。无第三方库、无 npm、无构建步骤，
原生 ES Module + Canvas + WebAudio。伴奏由 WebAudio 按谱面的 BPM 现场合成（8-bit 味）。

## 怎么开

在本目录下起任意静态服务即可：

```bash
python -m http.server 8000
```

浏览器打开 `http://localhost:8000/`。

> 不要直接双击 `index.html`（`file://` 下 `fetch` 谱面会被浏览器拦截）。
> 建议用 Chrome / Edge；首次点“开始演奏”同时也是浏览器解锁音频的手势。

## 操作

| 时机 | 按键 |
| --- | --- |
| 菜单 | Enter 开始，C 进入校准 |
| 演奏 | `D F J K` 对应从左到右四条轨道 |
| 演奏中 | Esc 暂停 / 继续（切窗口最小化也会自动暂停） |
| 暂停层 | 继续，或放弃本局回菜单 |

## 谱面

谱面文件固定为 `samples/chart.json`，游戏启动时读取，格式：

```json
{
  "meta": { "title": "曲名", "artist": "作者" },
  "bpm": 128,
  "offsetMs": 1875,
  "notes": [ { "timeMs": 2343.75, "lane": 0 } ]
}
```

- `lane`：0–3，对应左到右四轨。
- `timeMs`：歌曲时间（毫秒，浮点）。歌曲时间 0 = 音频起点；`offsetMs` 标记第 0 拍位置。
- 加载器（`src/chart.js`）对字段做了兼容：`offset`/`offset_ms`、`time`/`ms`、
  `column`/`track`，甚至 `[timeMs, lane]` 数组写法都能识别；非法/缺字段的音符会被跳过，
  重复音符去重，最后按时间排序。

**注意：仓库里的 `samples/chart.json` 是占位谱面**（`scripts/generate-chart.mjs` 生成，
3 分钟、804 音符、128 BPM），因为开工时真实谱面文件不在 `samples/` 下。
拿到真谱面后直接覆盖该文件、刷新页面即可，代码不需要改。
如需重新生成占位谱面：`node scripts/generate-chart.mjs`。

## 判定窗口（最终采用值）

以“按键时刻 − 音符时刻”的绝对值判定，**边界值包含在内**：

| 判定 | 时间差 |
| --- | --- |
| Perfect | ≤ 30 ms |
| Great | 31 – 60 ms |
| Good | 61 – 100 ms |
| Miss | > 100 ms（空按不扣连击；音符越过判定线 100 ms 仍未被击中也自动 Miss） |

窗口常量在 `src/config.js` 的 `WINDOWS`（`perfect: 30 / great: 60 / good: 100`），
改数值后同步本文件即可。

## 计分与准确率

- 单个音符：`基础分 + min(连击数 × 2, 100)`，Miss 为 0 且连击清零。
  - Perfect 1000 / Great 600 / Good 300。
  - 即 Perfect 最高 1100 分/键，排行榜直接按总分排序。
- 准确率只看判定档位，与连击无关：Perfect 权重 1.0、Great 0.6、Good 0.3、Miss 0。
- 评级按准确率：S ≥ 98%，A ≥ 93%，B ≥ 85%，C ≥ 70%，其余 D。

结算页给出四档计数、最大连击、准确率、总分与评级；输入名字后存入本机排行榜。

## 校准（解决键盘/显示器延迟）

菜单点“键盘/屏幕校准”（或按 C）：

1. 页面以 120 BPM 播放 4 个拍点声，同时有圆圈收缩动画。
2. 听到/看到拍点时按任意游戏键，共四下。
3. 每下计算偏差 `偏差 = 敲击时刻 − 拍点时刻`（毫秒），取 **4 个偏差的中位数**
   作为本机偏移 `offsetMs`，四舍五入到整数毫秒。
4. 保存后写入 `localStorage`，下次打开自动沿用；菜单上会显示当前校准值。
   也可以在校准结果页选择不保存或重校。

判定时：`比较用的时间差 = (按键歌曲时刻 − 音符时刻) − offsetMs`。
偏移为正（你整体系性按晚，常见于键盘扫描+显示器+耳机延迟）时，判定窗口整体往前补，
所以未校准和校准后的成绩会明显不同（HUD 左上和排行榜都会标出当局用的偏移）。

- 偏差 >250 ms 的点视为走神，不参与中位数，但仍在结果里展示；少于 4 下时按已有数据计算。
- 校准结果同时包含“平均绝对偏差”，用来判断你是整体延迟（靠中位数补）还是单纯手不稳。
- 校准用的拍点声和拍点显示共用同一个 AudioContext 时钟，所以校准测量的是
  “从声音发生到浏览器收到按键”的完整链路延迟，与游戏内的补偿口径一致。

## 时间轴（为什么高刷屏 / 掉帧不会偏）

核心原则：**音频时钟是唯一时间真相，画面只是跟着渲染**。

- `AudioContext.currentTime` 与音频输出硬件绑定，不随屏幕刷新率变化。
- `src/transport.js` 建立映射：歌曲 0 ms = 某个 `AudioContext` 时刻；
  键盘事件和 `requestAnimationFrame` 拿到的都是 `performance.now()` 域时间戳，
  再用两个时钟的固定差值换算到歌曲时间。判定使用换算后的歌曲时间，与帧率无关。
- 伴奏在 `src/audio.js` 里按谱面 BPM/offsetMs 预先换算成歌曲时间事件，
  由前瞻调度器（每 25 ms 排未来 120 ms）送到音频时钟，**不使用 setTimeout/setInterval 打节奏**，
  所以音乐和判定天然是同一条时间轴。
- 每帧只做两件事：按当前歌曲时间画音符；扫描“早于当前时间 100 ms 仍未击中”的音符记 Miss。
  掉一帧只是少画一帧、少扫一次，下一帧按音频时钟补齐，判定结果不变。
- 视觉上音符走 1400 ms 到判定线（`APPROACH_MS`，可调），这只影响观感。

### 暂停怎么保证不错位

Esc 暂停时：取消所有已排程但还没发声的音符，记录暂停时刻（音频时钟）；
恢复时把“暂停挂起的时长”累加到时间映射里，排程游标回退到当前位置之后重新排。

- 暂停那段真实时间**不计入歌曲时间**，音符停在原地，回来无缝继续。
- 判定、合成共用这一份映射，所以恢复后音乐和判定仍然对齐。

### 换分辨率 / 全屏 / 拖窗口

Canvas 按 CSS 尺寸 × `devicePixelRatio`（上限 2，避免 4K 下过度绘制）渲染，
`resize` 时只重算布局（轨道宽、判定线位置）。所有音符纵向位置每帧按歌曲时间反推，
横向只取相对比例，因此任何分辨率/全屏切换都不会产生时间或判定漂移。

## 成绩导入导出

- **导出**：菜单“导出成绩 JSON”，内容在底部文本框并自动尝试复制到剪贴板，发群即可。
- **合并**：另一台机器点“合并成绩 JSON”，把群里的文本粘进文本框，点框外任意位置；
  按记录 id 去重合并，重新按分数排序。
- 所有成绩、校准、上次使用的名字都在 `localStorage`（键名前缀 `rhythm-game:`），
  “清空榜单”只清成绩，不影响校准。

## 目录与可单独跑的纯逻辑

```
src/
  config.js          判定窗口、计分、速度等所有可调常量
  judge.js           纯计算：档位判定、找击中音符、收集 Miss
  score.js           纯计算：单音得分、准确率、评级、ScoreBoard
  calibrate.js       纯计算：偏差、中位数、校准结果
  chart.js           谱面加载与归一化（宽容字段）
  transport.js       纯计算：音频时钟 <-> performance 时钟、暂停映射
  audio.js           WebAudio 合成与前瞻调度
  render.js          Canvas 绘制（无游戏状态逻辑）
  input.js           键盘事件
  game.js            一局的编排
  calibration-screen.js / main.js   界面流程
tests/
  core.test.js       node --test 纯逻辑单测
  simulate.mjs       无头模拟整曲（全 Perfect / 暂停 / 固定偏差 / 挂机）
  browser-smoke.mjs  系统浏览器无头加载冒烟（--dump-dom）
  gameplay-smoke.mjs 系统浏览器 CDP 玩法冒烟（判定、暂停冻结、恢复）
```

跑测试（全部只用 Node 内置能力，不装东西）：

```bash
node --test tests/
node tests/simulate.mjs
node tests/browser-smoke.mjs       # 需要本机有 Edge/Chrome，没有会自动跳过
node tests/gameplay-smoke.mjs      # 同上
```

## 已知边界

- 只有普通音符（Tap），没有长条/按住——按需求先不做。
- 空按（窗口内没有音符时按键）不断连、不扣分，只闪轨道。
- 自动暂停发生在切标签页/窗口失焦时；部分浏览器后台会节流 rAF，回到前台即恢复对齐。
